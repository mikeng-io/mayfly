Project summary & conclusion · 2026-07-07

Mayfly

Ephemeral GitHub Actions runners on AWS Lambda MicroVMs — born, run one job, die.

Each CI job resumes a warm, suspended MicroVM, registers just-in-time for a single job, reaches your private AWS resources through a policy-gated VPC connector, and is destroyed on completion. No standing fleet. Per-job VM isolation. Scale-to-zero.

How we got here

Started as

A regional proxy

"Meridian" — can a MicroVM be a Control-D-style regional egress gateway? Route selected traffic through a chosen region.

Hit a wall

Serverless ✗ transparent

A transparent proxy needs an always-on L4 box. MicroVMs are L7-only; Lambda can't take a raw socket. So a serverless proxy can't exist — you'd just subscribe to Control D.

Landed on

Mayfly

MicroVM's real strength is isolated, stateful, VPC-connected compute, not networking. The honest fit: ephemeral CI runners.

What it is

The runner lifecycle, end to end:

Suspended
Booted with toolchain, un-registered, ~zero cost.

Wakes in ms; attaches its policy-scoped VPC access.

isolated
Run
One job, in its own VM, with private reach.
done
Die + refill
Terminated; a replacement is warmed to hold the pool.

Architecture at a glance

WebhookLambda + Function URL — verifies GitHub workflow_job events; enqueues provision / teardown.
Control planeLambda — resume a MicroVM, inject a JIT ephemeral runner config, terminate + refill on completion.
Runner imageMicroVM — Actions agent + toolchain baked in; JIT-registers on resume, runs one job.
Access policyGovernance pillar — maps branch / trust-level → which VPC connector + SG (fork PRs: none). "Invisible fences" for CI.
StateDynamoDB — pool + job↔VM mapping; the desired-vs-observed source of truth.
ReconcilerEventBridge Scheduler — sweeps leaked VMs, refills the pool, enforces a max-runtime cap. The SRE backbone.
EverythingTypeScript + AWS CDK — one toolchain, reproducible cdk deploy.
