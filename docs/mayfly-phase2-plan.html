What Phase 2 does

The make-or-break question

Does a real Lambda MicroVM stay RUNNING while the runner long-polls GitHub (outbound) and executes a job — handed its JIT config over the real L7 endpoint (X-aws-proxy-auth)?
Docs say auto-suspend follows inbound traffic; the runner is outbound, so we tune the idle policy and confirm empirically.

1CDK deploy the S3 artifact bucket + IAM build role. all resources via CDK · destroyable
2Build image: zip the app (launcher + Dockerfile) → S3 → create-microvm-image → wait CREATED.
3run-microvm with the idle policy tuned not to auto-suspend mid-job; wait for RUNNING.
4create-microvm-auth-token → POST the JIT config to the MicroVM endpoint (X-aws-proxy-auth, port 8080).
5Dispatch the workflow → the runner inside picks up the one job.
6Watch: poll the MicroVM state vs. the job — does it stay RUNNING the whole time?
7terminate-microvm (automatic on exit — nothing lingers, few cents).
PASS = MicroVM stays RUNNING throughout  +  workflow conclusion success  +  launcher /status reports done:true, code:0.
