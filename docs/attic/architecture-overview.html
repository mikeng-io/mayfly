Meridian · architecture & flow · as of 2026-07-07

Ephemeral regional egress on Lambda MicroVMs

A developer routes only policy-matched API calls through a chosen AWS region, leaving from a stable, allowlistable IP. Everything else goes direct. The gateway is disposable — the session lives as intent in DynamoDB, never as a held connection.

Use case: individual developer Trust: single domain Model: C′ (agent + MicroVM + control edge) Status: design settled · build not started

A matched request, cold start

Your app makes a call to api.example.com. The agent matches it against the policy → route to region R.
Agent calls the CloudFront discovery domain. The edge function validates the token and checks KeyValueStore — miss (no gateway yet), so it forwards to the origin.
The control edge resolves the region (substituting if R isn't a GA region), sees no live MicroVM, and calls run-microvm.
It mints a scoped JWE credential, writes the session intent to DynamoDB, write-throughs the endpoint to KeyValueStore, and returns {endpoint, credential}.
Agent opens an HTTP/2 CONNECT stream to the MicroVM endpoint (credential attached) and keeps the tunnel warm for later flows.
The MicroVM re-validates the destination against its baked-in policy, then dials the target — egressing through the NAT gateway's Elastic IP.
Bytes relay back through the tunnel. The next matched flow reuses the warm tunnel; the next lookup is now a KeyValueStore hit at the edge.

Two paths, one policy

Matched destinations

tunnel → region → stable IP

Rules like match "api.x" → gateway region send the flow through the agent's tunnel to a regional MicroVM, out a fixed IP. This is the minority of traffic.

Everything else

direct → internet

Rules like match "*.github.com" → direct — and the default — leave the machine normally. Meridian never sees them, so it cannot become a full tunnel.

What's decided — and what's deliberately out

Load-bearing decisions

intentState is intent, not connections. A session is rebuilt from a DynamoDB row: who, which region, which policy, which epoch.
enforce×2Selectivity is enforced twice — at the agent (fast path) and re-validated at the MicroVM (authoritative, since the client is untrusted).
no route53DNS does discovery, not routing. Edge geo + KeyValueStore replace Route53 placement; one CloudFront name is all that's configured.
1 : user·regionOne MicroVM per (user, active region) — typically 1–2 live, suspended when idle. Not per-session; not a big pool.

Honest limits & non-goals

8h seamThe 8-hour cap forces a reconnect. Continuous single flows longer than that are out of scope — no TCP handoff, by design.
5 regionsMicroVMs are in 5 regions at GA (Tokyo yes, Singapore no). Named-but-unavailable regions substitute at write time, recorded explicitly.
not a vpnNot a full tunnel, not multi-tenant (v1), not a DNS resolver. Default is direct; only matched destinations route.
